# 구조와 검증 범위

`app.py`는 파일 선택, 권한 자기 확인, 작업 스레드, 진행/취소 UI를 담당합니다.
`catalog.py`는 데이터 전용 JSON을 검증합니다. 외부 코드 실행이나 다운로드 기능은 없습니다.
`engine.py`는 입력 검증 → 사용자 템플릿 준비 → 선택 음원별 생성 → 검증 → 완료 폴더 확정을 담당합니다.
`pin_format.py`는 확인된 XOR PIN 형식의 읽기 전용 파서입니다.

현재 adapter인 `saypen-xor-book-v1`은 RTR-4000BS V0042에서 검증한 책 선택 경로를 사용합니다.
헤더/인덱스 배치를 유지하고 일반 로컬 슬롯을 비운 뒤, 특수 음원 할당 영역은 그대로 복사해 재배치합니다.
이후 사용자 MP3를 추가하고 책 시작 메타데이터의 시작 섹터와 길이를 지정합니다.
기존 음원을 포함하지 않는 완전 신규 PIN 방식은 실기 검증되지 않았으므로 적용하지 않았습니다.

## 확인된 구조

- 64바이트 반복 XOR 키는 코드에 있는 포맷 상수입니다. 입력 PIN 데이터 자체는 저장소에 포함하지 않습니다.
- 0x40부터 특수 레코드 94개 × 16바이트.
- 0x620에 책 시작 레코드 32바이트. +25 BE24가 시작 섹터, +28 BE16이 길이 섹터.
- 0x640부터 일반 슬롯 63078개 × 32바이트. 이 앱은 해당 영역을 비웁니다.
- 최초 오디오 위치 0x1EDA00을 유지합니다. 시작·길이는 512바이트 섹터 단위이며 할당 뒤 2048바이트 가드를 유지합니다.
- 일부 특수 레코드에는 추가 음원 3쌍을 담은 보조 테이블 포인터가 있습니다. 이 참조도 재배치합니다.
- 알 수 없는 헤더 값은 임의로 보정하지 않고 거부합니다. 추가 형식을 지원하려면 파서와 테스트를 확장해야 합니다.

## 확장 경계

같은 adapter의 다른 책은 JSON만 추가할 수 있습니다. 다른 장치/코드 분기/컨테이너는 새로운 adapter ID 및 별도 생성기를 구현하고 사용자 실기 검증을 거쳐야 합니다. 기본 도서 목록이 장치 호환성을 자동 증명하지 않습니다.

## 파일 안전성과 개인정보

원본은 읽기 전용으로 열며 기존 출력 이름에 덮어쓰지 않습니다. 생성 중 파일은 고유 `.partial` 폴더에 저장하고 성공 시에만 BOOK 및 완료 폴더로 이름을 바꿉니다. 중간 실패 폴더는 자동 삭제하지 않습니다.
취소는 파일 생성 단계 경계에서 확인합니다. 파일 읽기·검증이 진행 중이면 즉시 끝나지 않을 수 있습니다.
결과 manifest에는 음원/템플릿 해시, 책/모드/파일명이 기록되며 입력 파일의 절대 경로는 기록하지 않습니다. 프로젝트/경로 저장 기능이나 원격 전송은 없습니다.

MPEG 검사는 연속 프레임·경계 검사이며 실제 디코더의 청취 검사를 대체하지 않습니다. 정적 분석에서 전체 CRC 검사를 발견하지 못했지만 모든 펌웨어 경로에 CRC가 없다고 주장하지 않습니다.

## 확인 결과

원본 템플릿 3145894를 사용했을 때 앱 출력 24개는 사용자 실기 성공 경량화 24개와 바이트 단위로 일치했습니다. 이것은 해당 조합의 회귀 검증입니다. 다른 템플릿/펌웨어/신규 도서는 별도로 실기 확인해야 합니다.
